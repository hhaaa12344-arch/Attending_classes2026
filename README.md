# بوت تسجيل حضور الطلبة عبر تليجرام

نظام لتسجيل حضور الطلبة اليومي لدروس صوتية موزعة على مراحل دراسية ومواد متعددة، مع ربط تلقائي بقنوات نشر الدروس.

## الميزات

- تسجيل الطالب مرة واحدة (اسم رباعي + مرحلة)، وتسجيل حضور يومي بضغطة زر.
- قوائم الطالب والأدمن ثابتة أسفل شاشة تليجرام؛ فتح «دروس اليوم» أو أي شاشة داخلية لا يخفي قائمة الطالب.
- كل درس يُفعَّل (يدويًا أو تلقائيًا) يبقى متاحًا لتسجيل الحضور لمدة 24 ساعة (قابلة للتعديل).
- **ربط تلقائي بقنوات تليجرام**: يمكن ربط قناة أو أكثر بكل مرحلة. أي منشور داخل قناة مرتبطة يحتوي على **صوت أو ملف صوتي أو فيديو أو رابط** مع **هاشتاغ اسم المادة** (مثل `#المحاسبة`) يُفعّل الدرس تلقائيًا لتلك المادة، ويصل إشعار لجميع طلبة المرحلة.
- يتعامل البوت مع إضافة الهاشتاغ عند النشر **أو عند تعديل المنشور لاحقًا**.
- يصل للطالب **تنبيه واحد فقط في اليوم** عند بدء نشر دروس مرحلته، ولا يتكرر التنبيه مع كل درس جديد في اليوم نفسه.
- تعرض قائمة «دروس اليوم» زرًا واحدًا فقط للانتقال إلى قناة الدروس، ثم زر تأشير مستقل لكل درس غير مكتمل. ويختفي الدرس من القائمة فور تأشير «تم الاستماع».
- أزرار البوت ملوّنة بحسب وظيفتها (أساسي/تأكيد/تحذير)، مع زر «↩️ رجوع» للخروج من أي خطوة إدخال والعودة إلى القائمة الرئيسية.
- ينظف البوت رسائل تنقّل الطالب السابقة تلقائيًا عند فتح شاشة جديدة، مع إبقاء إشعارات الدروس والتنبيهات وقرارات الإجازة المهمة ظاهرة.
- يستطيع الأدمن مراجعة هاشتاغات المواد وتعديلها، ويصله تنبيه واضح عند فقد الهاشتاغ أو عدم مطابقته.
- يمكن استخدام الهاشتاغ نفسه في مراحل مختلفة، مثل `#الفقه` في كل المراحل؛ المطابقة تعتمد على قناة المرحلة، ويُمنع التكرار داخل المرحلة نفسها فقط.
- **مواسم دراسية مستقلة لكل مرحلة**: يمكن بدء موسم جديد لمراحل محددة وترك المراحل السنوية في موسمها الحالي.
- عند بدء الموسم يختار الطالب إعادة مرحلته أو الانتقال إلى المرحلة الأعلى التي حددها الأدمن، وتبقى تقارير الموسم السابق محفوظة.
- يستطيع الطالب قراءة تقرير لكل مرحلة وموسم كرسالة، ويستطيع الأدمن تنزيل تقرير طالب أو مرحلة كاملة لأي موسم سابق.
- **إدارة المراحل**: تعديل الاسم، تحديد المرحلة الأعلى، وأرشفة المرحلة أو استعادتها من دون حذف تاريخها، أو حذفها نهائيًا مع كل بياناتها.
- يسمح بنشر عدة دروس للمادة نفسها في اليوم وفي أي وقت؛ كل منشور جديد يُفعّل درسًا مستقلًا بمهلة 24 ساعة خاصة به. ولا تتكرر معالجة المنشور نفسه عند تعديله.
- **تذكير تلقائي**: قبل ساعتين من انتهاء مهلة الدرس، يصل تذكير لكل طالب لم يسجّل حضوره بعد، مع استثناء الطالب الموجود في إجازة معتمدة في ذلك اليوم.
- **تنبيه الغياب المتتالي**: إذا انتهت مهل جميع دروس 3 أيام دراسية متتالية بلا تسجيل أي حضور، يصل تنبيه للطالب. وإذا استمر الغياب الكامل إلى 10 أيام، تصل للأدمن قائمة مجمعة بأسماء الطلبة من جميع المراحل.
- **إدارة الطلبة**: بحث بالاسم، تعديل الاسم، نقل المرحلة مع بقاء سجل الطالب السابق، وحذف الطالب بنوعين: **أرشفة** (يبقي كل بياناته) أو **حذف نهائي** (يمحوه مع كل سجلاته).
- **حذف المواد نهائيًا** مع كل دروسها وحضورها من شاشة «المواد والهاشتاغات».
- **نظام الإجازات**: يرسل الطالب عدد الأيام فقط (`1` أو `١` أو `۱` مثلًا)، ويحدد البوت تاريخ البداية تلقائيًا من يوم الطلب حسب توقيت بغداد. رصيد كل طالب **10 أيام لكل موسم دراسي**؛ تُحتسب الإجازات المعتمدة والطلبات المعلّقة عند فحص المتبقي، ويُرفض أي طلب يتجاوز الرصيد. عند الموافقة لا تصله إشعارات الدروس ولا تذكيراتها في أيام إجازته، ولا تُحسب تلك الأيام غيابًا وتقطع سلسلة الغياب المتتالي. يبقى تأشير كل درس مقيدًا بمهلته الأصلية، ولا يمكن تأشيره بعد انتهائها.
- يعرض زر **«📋 المتغيرات»** بجانب طلب الإجازة: تظهر داخله الإجازات المعتمدة، ولا يظهر قسم التنبيهات إلا إذا كان الطالب قد تلقّى تنبيه غياب فعلًا خلال موسمه الحالي.
- **تأكيد التسجيل الرسمي**: عند أول استخدام تظهر رسالة الترحيب والتنبيه الشرعي مع زر «أؤكد أنني مسجّل بصفة طالب رسمي»، ولا تُفتح وظائف الطالب قبل الضغط عليه.
- **تقرير حضور تاريخي** لكل طالب أو مرحلة وموسم كملف Markdown (.md) يُقرأ مباشرة على الهاتف، ويتضمن عمودًا مستقلًا لتواريخ وأوقات تسجيل الحضور، وعدد أيام الإجازة المعتمدة وتواريخها.

## هيكل الملفات

```
index.js     — منطق البوت الكامل
db.js        — الاتصال بقاعدة البيانات وإنشاء/ترقية الجداول تلقائيًا واستعلامات SQL
utils.js     — تحليل الهاشتاغات والروابط ومحتوى منشورات تليجرام
test/        — اختبارات آلية للوظائف الحرجة وتسجيل معالجات البوت
package.json — الاعتماديات (telegraf, pg, dotenv)
.env.example — نموذج للمتغيرات البيئية المطلوبة
```

قاعدة البيانات تُنشأ وتُرقّى تلقائيًا عند كل تشغيل (لا حاجة لتشغيل SQL يدويًا، وآمن عند تحديث نسخة قديمة من البوت).

## خطوات النشر على Railway (خطة Hobby)

### 1. إنشاء البوت في تليجرام
تحدث مع [@BotFather](https://t.me/BotFather)، أرسل `/newbot` واحصل على **BOT_TOKEN**.

### 2. معرفة معرف تليجرام الخاص بك (لتكون أدمن)
تحدث مع [@userinfobot](https://t.me/userinfobot) للحصول على رقم معرفك (Telegram ID).

### 3. رفع المشروع إلى GitHub
```bash
git init
git add .
git commit -m "Initial commit: telegram attendance bot"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

### 4. النشر على Railway
1. **New Project → Deploy from GitHub repo** واختر المستودع.
2. **New → Database → Add PostgreSQL** داخل نفس المشروع (يوفّر `DATABASE_URL` تلقائيًا).
3. من **Variables** في خدمة البوت أضف:
   - `BOT_TOKEN` = التوكن من BotFather
   - `ADMIN_IDS` = معرفك (أو عدة معرفات مفصولة بفواصل)
   - `LESSON_ACTIVE_HOURS` = 24 (اختياري)
   - `ATTENDANCE_TIME_ZONE` = Asia/Baghdad (اختياري، وهذا هو الافتراضي)
4. Railway يشغّل تلقائيًا `npm install` ثم `npm start`.
5. جرّب `/start` للتسجيل، و`/admin` من حسابك للوحة التحكم.

### ملاحظة حول خطة Hobby
أبقِ عدد نسخ التشغيل (Replicas) = 1 لأن حالة الإدخال المؤقتة (كالاسم قيد الكتابة) محفوظة في ذاكرة العملية. هذا هو الإعداد الافتراضي، فلا حاجة لأي تغيير عادةً.

## ربط قناة بمرحلة (خطوة تُنفَّذ مرة واحدة لكل مرحلة)

1. أضِف البوت **كأدمن** داخل قناة تليجرام الخاصة بالمرحلة (تكفي صلاحية نشر الرسائل).
2. من `/admin` اختر **"🔗 ربط قناة بمرحلة"**.
3. حوّل (Forward) أي منشور من داخل القناة إلى البوت في الخاص.
4. اختر المرحلة التي تمثلها هذه القناة من الأزرار.

بعدها، عند نشر أي درس داخل القناة (صوت، ملف صوتي، فيديو، أو رابط) **مع هاشتاغ اسم المادة**، مثل:

```
درس اليوم في مادة المحاسبة
https://youtu.be/xxxxxxxx
#المحاسبة
```

سيتعرف البوت تلقائيًا على المادة عبر الهاشتاغ، ويفعّل الدرس، ويرسل إشعارًا لجميع طلبة تلك المرحلة.

إذا نسيت الهاشتاغ، أضِفه بتعديل المنشور نفسه؛ سيتعامل البوت مع التعديل ويُفعّل الدرس. وإذا كان الهاشتاغ غير مطابق، يرسل البوت للأدمن تنبيهًا باسم القناة والهاشتاغ الذي لم يتعرّف عليه.

> **مهم:** الهاشتاغ يُحدَّد عند إضافة المادة (يمكنك اختياره بنفسك أو تركه يُولَّد تلقائيًا من اسم المادة بدون مسافات). تأكد أن الهاشتاغ في منشور القناة مطابق تمامًا لهاشتاغ المادة المسجَّل في البوت.

## إعداد المراحل والمواسم

### تحديد مسار الانتقال

من `/admin` افتح **«⚙️ إدارة المراحل»**، ثم افتح كل مرحلة وحدد **المرحلة الأعلى** التي ينتقل إليها الطالب عند النجاح. هذا الربط صريح، ولا يعتمد على ترتيب إنشاء المراحل، ويمنع البوت إنشاء حلقة بين المراحل.

من الشاشة نفسها يمكنك:

- تعديل اسم المرحلة؛ يتحدّث اسم المرحلة المعروض في موسمها النشط، بينما تحتفظ المواسم المغلقة باسم المرحلة التاريخي وقت إغلاقها.
- أرشفة المرحلة بدل حذفها نهائيًا؛ تختفي من التسجيل والمواسم الجديدة وتبقى كل تقاريرها محفوظة.
- استعادة مرحلة مؤرشفة عند الحاجة.

### تسمية المواسم — تكتب الاسم، والبوت يضيف الوسم

الأدمن يكتب اسم الموسم كاملًا كما يريده (مثل «الموسم الأول 2026»)، ويُحفظ ويُعرض كما هو. يضيف البوت عند العرض وسمًا واحدًا فقط:

- **وسم نسبي**: «(الحالي)» للموسم النشط، و«(السابق)» للموسم الذي أُغلق قبله مباشرة فقط. المواسم الأقدم من ذلك تُعرض باسمها فقط.

مثال لما يظهر فعليًا: `الموسم الأول 2026 (الحالي)`، أو لموسم أقدم: `الموسم الأول 2024`.

عند بدء موسم لعدة مراحل دفعة واحدة، يُطبَّق الاسم الذي كتبته على كل المراحل المحددة (مثل «2026-2027»). لا يُقبل تكرار نفس الاسم لنفس المرحلة مرتين.

### بدء موسم جديد

1. افتح `/admin` واختر **«🗓️ بدء موسم جديد»**.
2. اكتب اسم الموسم كاملًا (مثل «الموسم الثاني 2026»).
3. حدد المراحل التي يبدأ لها هذا الموسم واضغط **«بدء الموسم للمراحل المحددة»**.
4. لا تتغير المراحل غير المحددة؛ لذلك تستطيع إبقاء مرحلة في موسمها الحالي وبدء موسم جديد لمراحل أخرى.
5. موسم المرحلة الذي كان «الحالي» يصبح تلقائيًا «السابق»، والموسم الجديد يصبح «الحالي».
6. يصل إشعار لطلبة المراحل المحددة. يختار كل طالب:
   - **إعادة المرحلة** في موسمها الجديد.
   - **نجحت — الانتقال إلى المرحلة الأعلى**، إذا كان الأدمن قد حدد مرحلة أعلى نشطة.

لا يسمح البوت ببدء موسم لاحق للمرحلة قبل أن يحسم طلبتها انتقال الموسم الجاري، حتى لا تضيع عليهم إمكانية الإعادة.

### تقارير المواسم

- الطالب يضغط **«📊 تقريري»**، فإن كان له أكثر من موسم يختار أيّها يريد عرضه (الحالي أو أي موسم سابق) من قائمة بأسمائها التلقائية؛ إن كان له موسم واحد فقط يُعرض مباشرة بلا قائمة.
- من **«🎓 إدارة الطلبة»** يستطيع الأدمن فتح الطالب ثم **«تقرير كل المواسم»**؛ يرسل البوت الملخص النصي وملف Markdown بكل مواسمه دفعة واحدة.
- من **«📊 تقرير الحضور»** يختار الأدمن المرحلة ثم الموسم لتنزيل تقرير المرحلة الكامل.
- من **«🗂️ أرشيف المواسم»** يختار الأدمن المرحلة فيرى كل مواسمها (بتسميتها التلقائية) وعدد الطلبة والدروس في كل موسم، ثم يختار أيها يريد تنزيل تقريره.

## الاستخدام اليومي

**للأدمن:**
1. أول مرة: أضِف المراحل الـ12، ثم أضِف مواد كل مرحلة (مع هاشتاغ لكل مادة)، ثم اربط قناة كل مرحلة.
2. يوميًا: انشر الدرس في القناة بالهاشتاغ الصحيح — التفعيل والإشعار يحدثان تلقائيًا. (أو فعّل يدويًا من "🟢 تفعيل درس يدويًا" إن لزم).
3. عند الحاجة: "🎓 إدارة الطلبة" للبحث عن طالب وتعديل بياناته أو أرشفته أو تنزيل تقريره.
4. "🏷️ المواد والهاشتاغات" لمراجعة الهاشتاغات أو تعديلها.
5. "⚙️ إدارة المراحل" لتعديل الاسم وتحديد المرحلة الأعلى والأرشفة أو الاستعادة.
6. "🗓️ بدء موسم جديد" للمراحل التي تختارها فقط.
7. "📊 تقرير الحضور" و"🗂️ أرشيف المواسم" لمراجعة المواسم الحالية والسابقة.

**للطالب:**
1. `/start` (أول مرة فقط) → الاسم الرباعي → اختيار المرحلة → الضغط على زر تأكيد التسجيل بصفة طالب رسمي.
2. يوميًا عند وصول إشعار الدرس، أو بشكل دوري: "📚 دروس اليوم" → "📢 انتقال إلى دروس اليوم" → "✅ تم الاستماع". بعد التأشير يظهر اسم المادة ورقم الدرس وتبقى بقية دروس اليوم ظاهرة.
3. سيصله تذكير تلقائي إن لم يسجّل حضوره قبل ساعتين من انتهاء المهلة.
4. يضغط "📊 تقريري" ويختار أي موسم يريد الاطلاع عليه (الحالي أو أي موسم سابق).

## قابلية التوسع لاحقًا
- لوحة ويب للتقارير إذا زاد عدد الطلبة كثيرًا وأصبح التصفح داخل تليجرام غير مريح.
- تصدير تقرير تلقائي دوري (أسبوعي) يُرسَل للأدمن مباشرة دون طلب.

## سجل التغييرات

### 2.15.0 — تحسينات واجهة الأستاذ ودرجة حضور الدروس

- **🙈 إخفاء الأزرار**: يخفي لوحة الأزرار الثابتة، وتعود بـ `/start` أو `/menu` (أمر جديد يعيد لوحتك حسب دورك: أدمن أو أستاذ أو طالب).
- **🧹 تنظيف المحادثة**: يحذف رسائل البوت المتراكمة في المحادثة. (تليجرام لا يسمح بحذف ما مضى عليه أكثر من 48 ساعة، ولا برسائلك أنت في المحادثة الخاصة.)
- **📋 تقارير الدروس**: يستعرض الأستاذ حضور طلبة المادة في الدروس كملف Markdown (حضر / الإجمالي / النسبة / الدرجة الممنوحة)، ثم **يمنح كل طالب درجة حضور الدروس** بالضغط على اسمه. **ويصل الطالب إشعار بدرجته فور منحها**، وتظهر له في «🎯 درجات - المباحثات» وتُحتسب ضمن مجموعه.
- **🔗 روابط المجموعات**: شاشة تجمع كل مجموعات مواد الأستاذ مع عدد أعضائها وأزرار تنقله إلى كل مجموعة مباشرة، وتُبيّن ما ينقصه رابط دعوة.
- **الامتحانات تبدأ العاشرة ليلًا**: صار الامتحان يفتح الساعة 22:00 من اليوم المختار ويستمر عدد الساعات الذي يحدده الأستاذ (بدل بداية اليوم). قابل للضبط عبر `EXAM_START_HOUR`، والتأجيل يحافظ على نفس ساعة البدء.
- **زر الطالب**: صار اسمه **«🎯 درجات - المباحثات»** بدل «درجاتي».


### 2.14.1 — تصحيح عدّ الطلبة في لوحة المعهد

- **خطأ في العدّ**: كانت اللوحة تعدّ أزواج (طالب × مادة) لا الطلبة أنفسهم، فيظهر طالب واحد له ثلاث مواد على أنه **«3 طلاب لم يختاروا نمط مشاركتهم»**. صار العدّ للطلبة المميّزين، فيُحسب الطالب مرة واحدة مهما تعددت مواده الناقصة. ونفس التصحيح طُبّق على «الطلبة الذين لم يُوزَّعوا على مجموعة».
- **توضيح الصياغة**: صار السطر يقول «لم يختاروا نمط مشاركتهم **في مادة واحدة على الأقل**» ليكون المعنى دقيقًا، لأن الطالب قد يكون اختار في بعض مواده دون بعض.
- **التقارير غير المقيَّمة** تُعرض بعددها وبعدد الطلبة أصحابها معًا (مثل: «5 تقارير لم تُقيَّم (لـ2 طالبًا)») لأن العدد الأول عن التقارير والثاني عن الطلبة، وخلطهما كان يربك القراءة.


### 2.14.0 — نوع المرحلة: حضور دروس فقط أو مرحلة كاملة

بعض المراحل لا تشمل مباحثات ولا تقارير ولا امتحانات، فصار نوع المرحلة يُحدَّد **عند إنشائها**:

- **📚 حضور دروس فقط**: يستمع الطالب للدروس ويؤشّر حضوره، ويطلب الإجازات، ويرى تقريره. **لا تظهر له** أزرار المباحثات ولا التقارير ولا الامتحانات ولا الدرجات — فلا يُعرض عليه ما لا ينطبق على مرحلته.
- **🎓 كاملة**: كل شيء — دروس + مباحثات أو تقارير + امتحانات شهرية ودرجات.

وأثر ذلك في بقية النظام:
- **مواد مراحل «الدروس فقط» لا تظهر** للأستاذ ولا للأدمن في شاشات المجموعات والجدول والامتحانات وإنهاء الموسم، فلا تُنشأ لها مجموعات أو امتحانات بالخطأ.
- **لوحة المعهد تتجاهلها** في إدارة الاستثناءات، فلا تُحسب موادها «بلا أستاذ» ولا طلبتها «بلا نمط مشاركة».
- **يمكن تغيير نوع المرحلة لاحقًا** من «⚙️ إدارة المراحل» ← المرحلة ← «🎓 نوع المرحلة».
- المراحل المُنشأة قبل هذه الميزة تبقى **كاملة** كما كانت، فلا يتغير سلوك أي مرحلة قائمة عند الترقية.


### 2.13.0 — تأجيل الامتحانات، المباحثة ساعة واحدة، وإصلاحات أمنية

**ميزتان جديدتان:**
- **🕓 تأجيل الامتحان**: يستطيع الأستاذ تأجيل امتحان منشور إلى تاريخ جديد وتحديد مدة إتاحة جديدة. تُلغى المحاولات التي لم تُسلَّم ليبدأ الجميع من الصفر، ويُحفظ التاريخ الأصلي وعدد مرات التأجيل، **ويصل الطلبة إشعار بالموعد الجديد**. ويُرفض التأجيل إذا كان طالب واحد قد سلّم الامتحان فعلًا، حفاظًا على عدالة التقييم.
- **المباحثة ساعة واحدة كحد أقصى**: كل ساعة موعد مستقل. صُحّحت المدة الافتراضية من ساعتين إلى ساعة، وتُصحَّح المواعيد القديمة تلقائيًا عند الترقية.

**إصلاحات أمنية ومنطقية (بعد مراجعة خارجية تحققتُ من صحتها في الكود):**
- **منع دخول امتحان مرحلة أخرى**: كان بدء الامتحان لا يتحقق من تسجيل الطالب في موسم المرحلة، فأمكن نظريًا فتحه بضغطة زر معدّلة. صار التحقق من قاعدة البيانات إلزاميًا.
- **منع الإجابة بعد انتهاء المهلة**: كان الطالب الذي بدأ قبل الإغلاق يواصل الإجابة بعده. صار وقت الإغلاق يُفحص عند **كل إجابة**، وعند انتهائه يُسلَّم الامتحان تلقائيًا بما أُجيب عنه وتُعرض الدرجة.
- **التحقق من نمط المشاركة من قاعدة البيانات لا من الزر**: لم يعد ممكنًا إرسال تقرير لمادة لم يُختَر فيها نظام التقارير، ولا الانضمام لمجموعة مادة لم يُختَر فيها نظام المباحثات.
- **زر «إلغاء» صار يعمل للجميع**: كان مقصورًا على الأدمن، فيظهر للطالب والأستاذ «غير مصرح» بدل إلغاء العملية.
- توحيد ذكر صيغة التقارير في هذا الملف (Markdown في كل المواضع).


### 2.12.0 — لوحة المعهد، تغيير أستاذ المادة، وتحويل التقارير إلى Markdown

- **📈 لوحة المعهد (للأدمن)**: نظرة عامة على المراحل والمواد والطلبة والأساتذة والقنوات، ونشاط اليوم (الدروس المفعّلة، تسجيلات الحضور، جلسات المباحثة). وتحتها **إدارة الاستثناءات**: يعرض ما يحتاج تدخلك فقط — طلبة اختاروا المباحثات ولم يُوزَّعوا، طلبة لم يختاروا نمطهم، مجموعات بلا رابط دعوة، مواد بلا أستاذ، أساتذة لم يفعّلوا حساباتهم، طلبات إجازة معلّقة، امتحانات مسودة، تقارير غير مقيَّمة، ومراحل بلا قناة. ومعها تقرير مفصّل بكل المراحل.
- **🔄 تغيير أستاذ مادة أثناء الموسم**: كل بيانات المادة تنتقل للأستاذ الجديد (الطلبة، المجموعات، الجدول، الجلسات، الامتحانات) لأنها مرتبطة بالمادة والموسم لا بالأستاذ. وتُنقل ملكية **المواعيد والامتحانات** إليه ليصله السؤال اليومي عن المباحثة ويدير امتحاناته. ويصله فور التغيير **ملخّص تسليم** بكل ما تسلّمه، ثم **تُرسل إليه تلقائيًا كل التقارير التي لم تُقيَّم بعد**، ويُبلَّغ الأستاذ السابق بانتهاء مسؤوليته.
- **كل ملفات التقارير صارت Markdown (.md) بدل CSV** في البوت كله: تقرير الطالب، تقرير المرحلة والموسم، حضور المادة للأستاذ، نتائج الامتحانات، معاينة الدرجات، وتقرير المعهد. الملف يُقرأ مباشرة على الهاتف وفي تليجرام بلا برنامج جداول، ويحافظ على اتجاه النص العربي.


### 2.11.1 — التقرير يصل الأستاذ فور إرساله

- **تقرير الطالب يُرسل مباشرة إلى حساب أستاذ المادة الشخصي على تليجرام** بمجرد إرساله، فلا ينتظر الأستاذ نهاية الموسم ليطّلع عليه. يصله الملف أو الصورة أو النص مرفقًا باسم الطالب واسم المادة وتاريخ الإرسال.
- التقرير **يُحفظ في النظام أيضًا** كما كان، فيبقى متاحًا عند تقييم نهاية الموسم من «🏁 إنهاء الموسم».
- إذا كانت المادة مسنَدة لأكثر من أستاذ، يصل التقرير إليهم جميعًا.
- إذا لم يكن للمادة أستاذ مرتبط بحساب تليجرام، **يُبلَّغ الأدمن** بوصول تقرير لم يُسلَّم لأستاذ، فلا يضيع.
- يؤكَّد للطالب وصول تقريره إلى الأستاذ.


### 2.11.0 — واجهات الطالب: نمط المشاركة والمجموعات والتقارير (النظام صار قابلًا للتشغيل كاملًا)

كانت هذه آخر فجوة حرجة: منطق المباحثات والتقارير كان جاهزًا، لكن الطالب لم يملك أي زر يدخله في النظام أصلًا.

- **📖 مشاركتي**: يرى الطالب مواد مرحلته ونمط مشاركته في كل واحدة، ويختار لكل مادة على حدة: **المباحثات** أو **التقارير**. ويمكنه الدخول متى شاء لمراجعة حالته.
- **الانضمام التلقائي للمجموعة**: عند اختيار المباحثات يُوزَّع على أول مجموعة فيها متسع ويصله **زر الانضمام برابط الدعوة**. وإذا امتلأت كل المجموعات لا يُوزَّع خطأً، بل يُبلَّغ بالانتظار **ويصل الأدمن تنبيه** لإنشاء مجموعة جديدة. وكذلك إن كانت المجموعة بلا رابط دعوة.
- **📄 إرسال تقرير**: يختار المادة ويرسل **ملفًا (PDF/Word) أو صورة أو نصًا مكتوبًا**، فيُحفظ ويصل الأستاذ عند التقييم في نهاية الموسم.
- **🔁 التحويل من التقارير إلى المباحثات**: بشاشة تأكيد تُبيّن له أن الجلسات السابقة لتحويله لن تُحاسب عليه، وأن درجة تقاريره تبقى محسوبة له — ثم يُوزَّع على مجموعة فورًا.
- **🎯 درجاتي** و**🗓️ جدولي** و**📝 الامتحانات الشهرية** كما في الإصدارات السابقة.

- **📝 الامتحانات**: ثلاثة امتحانات لكل مادة. إنشاء الامتحان باختيار يوم من الأسبوع القادم وإدخال عدد ساعات الإتاحة، ثم إضافة أسئلة **صح/خطأ** و**اختيار من متعدد** (مختلطة أو من نوع واحد) بأزرار لتحديد الجواب الصحيح، ثم **النشر** الذي يرسل إشعارًا لكل طلبة المرحلة. وبعد النشر: **نتائج الامتحان كملف Markdown**، مع إمكانية **تأجيل الامتحان**.
- **🏁 إنهاء الموسم**: تقييم التقارير **طالبًا تلو الآخر** مع عرض سجله وعدد تقاريره وإرسال ملفاته للاطلاع قبل وضع الدرجة، ثم **معاينة الدرجات** كملف Markdown قبل الاعتماد، ثم **اعتماد درجات الموسم**.

### 2.6.1-alpha — الجدول الأسبوعي للمباحثات وتشغيلها تلقائيًا

- **الجدول الأسبوعي**: الأستاذ يبني جدول كل مجموعة باختيار يوم من أيام الأسبوع وساعة من الساعات المتاحة (تُعرض كأزرار: 8، 9، 10 …، ويمكن ضبطها عبر `SCHEDULE_HOURS`).
- **كشف التعارض**: عند إضافة موعد يُنبَّه الأستاذ إن كانت **مادة أخرى لنفس المرحلة** في اليوم والساعة نفسيهما، لأن طالب المرحلة يدرس كل موادها. أما مجموعتا المادة الواحدة في الوقت ذاته فلا تعارض بينهما، لأن الطالب في مجموعة واحدة فقط.

- **فتح الجلسة تلقائيًا**: عند حلول الوقت المحدد للموعد المؤكَّد تُفتح الجلسة ويصل طلبة المجموعة تنبيه فيه زر **«حضرتُ المباحثة»**، ويصل الأستاذ إشعار بعدد من بلغهم التنبيه. الجلسة لا تُفتح مرتين مهما تكرّر التحقق.
- **حماية تسجيل الحضور**: لا يُقبل إلا من عضو في مجموعة الجلسة نفسها، وضمن وقت الجلسة، ومرة واحدة فقط.
- تعمل الحلقة كل دقيقة، والتوقيت المحلي قابل للضبط عبر `SCHEDULE_TIMEZONE` (الافتراضي `Asia/Baghdad`).


### 2.6.0-alpha — طبقة نظام المباحثات والامتحانات (المرحلة 2 — البيانات فقط، الواجهات قادمة)

أُضيفت وحدة مستقلة `studies.js` تحتوي منطق نظام المباحثات والامتحانات كاملًا ومختبَرًا على قاعدة بيانات حقيقية. **الواجهات في تليجرام لم تُبنَ بعد** — هذه الطبقة الأساسية فقط.

- **أنماط المشاركة**: لكل طالب في كل مادة إما «مباحثات» أو «تقارير»، مع إمكانية التحويل للمباحثات؛ والجلسات التي سبقت تحويله **لا تُحسب عليه**، وتبقى تقاريره المُسلَّمة لتُضاف درجتها.
- **مجموعات المباحثات**: لكل مادة مجموعة أو أكثر بسعة محددة. عند امتلاء المجموعة يُوجَّه الطالب تلقائيًا إلى المجموعة التالية، وكل مجموعة تُعامل بشكل مستقل (جلساتها وحضورها). التوزيع داخل معاملة مع قفل الصفوف فلا تتجاوز السعة عند الضغط المتزامن.
- **الامتحانات الشهرية**: ثلاثة امتحانات لكل مادة في الموسم، كل امتحان **5 درجات مهما كان عدد أسئلته**، ويقبل الخلط بين صح/خطأ والاختيار من متعدد. الأستاذ يختار يومًا من أيام الأسبوع القادم فيحوّله البوت إلى تاريخ، ويحدد عدد ساعات الإتاحة. **التصحيح آلي بالكامل**، والامتحان **قابل للاستئناف**: كل إجابة تُحفظ فور اختيارها فيُكمل الطالب من حيث توقف لو انقطع الاتصال، ولا تُنشأ محاولة ثانية أبدًا. طلبة التقارير مشمولون بالامتحانات كطلبة المباحثات.
- **الدرجات**: امتحانات 15 (3×5) + مشاركة 15. درجة المباحثات نسبة وتناسب (حضر كل الجلسات ← 15 كاملة)، ودرجة التقارير يحددها الأستاذ عند إنهاء الموسم مستعرضًا سجل كل طالب. زر «إنهاء الموسم» يحسب الدرجات ويحفظها.

**افتراضان اتُّخذا حيث لم تُحدَّد التفاصيل** (قابلان للتعديل):
1. الامتحان يفتح في بداية اليوم المختار (00:00) ويُغلق بعد عدد الساعات المُدخَل.
2. الطالب المحوَّل من التقارير: درجة مشاركته = درجة تقاريره + درجة مباحثاته بعد التحويل، بحد أقصى 15.


### 2.5.0 — قنوات موسمية + نظام الأساتذة (المرحلة 0 و1 من نظام المباحثات والامتحانات)

**إصلاح القنوات (مهم لطريقة العمل بإنشاء قنوات جديدة كل موسم):**
- صارت القناة تُربط بـ**موسم المرحلة** لا بالمرحلة نفسها. عند بدء موسم جديد تتوقف قناة الموسم السابق **تلقائيًا** عن تفعيل الدروس، فلا يُفعِّل منشورٌ قديم — أو تعديلٌ على منشور قديم — درسًا في الموسم الحالي بالخطأ (كان هذا خطأً صامتًا يفسد بيانات الحضور).
- عند بدء موسم جديد يصل الأدمن تنبيه بأسماء القنوات التي توقفت، ليربط قنوات الموسم الجديد.
- شاشة «📡 القنوات المرتبطة» صارت تُظهر حالة كل قناة (🟢 نشطة / ⚪️ متوقفة) وفيها **زر فكّ الربط** (كانت الدالة موجودة في الكود لكن بلا أي زر في الواجهة).
- الترقية آمنة: القنوات المرتبطة حاليًا تُنقل تلقائيًا إلى الموسم النشط لمرحلتها وتستمر في العمل.

**نظام الأساتذة (جديد كليًا):**
- جدول أساتذة مستقل عن الأدمن، مع **كود تفعيل من 8 محارف لمرة واحدة**: يضيف الأدمن الأستاذ فيحصل على كود، يرسله الأستاذ للبوت فيُربط حسابه — بلا حاجة لمعرفة معرّف تليجرام مسبقًا.
- **إسناد المواد لكل موسم على حدة**، فيمكن أن يتغير أستاذ المادة بين موسم وآخر مع بقاء سجل كل موسم منسوبًا لأستاذه الحقيقي.
- **لوحة الأستاذ**: «📚 موادي» و«📊 حضور موادي» — يرى فقط المواد المسنَدة إليه، ويُنزّل تقرير حضور المادة كملف CSV.
- التقرير يطبّق مبدأ **إدارة الاستثناءات**: يُبرز المتأخرين عن الحضور أولًا بدل استعراض كل الطلبة.
- **إدارة الأساتذة للأدمن**: إضافة، إسناد وسحب المواد، إعادة توليد كود التفعيل، تعطيل/إعادة تفعيل، وحذف نهائي.


### 2.4.4 — رصيد الإجازات وتواريخ الحضور في CSV
- أصبح الحد الأعلى للإجازات 10 أيام لكل طالب في كل موسم، ويظهر له الرصيد المستخدم والمتبقي قبل تقديم الطلب وبعده.
- يُمنع تجاوز الرصيد داخل معاملة ذرية في قاعدة البيانات، مع احتساب الطلب المعلّق مؤقتًا وإعادة رصيده إذا سُحب أو رُفض.
- رُبطت كل إجازة بموسمها الدراسي، وتُربط الإجازات القديمة تلقائيًا بمواسمها عند الترقية.
- تعرض بيانات الطالب لدى الأدمن ملخص الحضور، والإجازات المعتمدة، وتواريخها، والرصيد المتبقي.
- أضيفت إلى تقارير CSV أعمدة تواريخ وأوقات كل تسجيل حضور، وأيام الإجازات المعتمدة وفتراتها.
- أُصلح تضمين اسم الموسم المكتوب من الأدمن داخل بيانات التقرير وملف CSV.
- عند إنهاء إجازة معتمدة مبكرًا تُحفظ الأيام التي بدأت فعليًا ضمن سجل الموسم ورصيده.

### 2.4.3 — تنبيه يومي واحد وقائمة دروس مختصرة
- أُلغي إرسال إشعار مستقل لكل درس؛ يتلقى كل طالب تنبيه نشر واحدًا فقط لكل مرحلة في اليوم حسب توقيت بغداد، مهما تعددت الدروس المنشورة.
- صار زر «📢 الانتقال إلى قناة الدروس» يظهر مرة واحدة فقط أعلى قائمة الدروس بدل تكراره مع كل مادة.
- تختفي الدروس المؤشَّرة من «📚 دروس اليوم» فور تسجيل الاستماع، ولا تبقى ظاهرة بزر «تم الاستماع».
- لا تكرر رسائل التذكير زر الانتقال إلى القناة؛ تعرض زر تأشير الدرس المعني فقط.
- أضيف حجز ذري للتنبيه اليومي في قاعدة البيانات لمنع تكراره عند وصول عدة منشورات متزامنة، ويُلغى الحجز إذا فشل الإرسال لتتاح المحاولة لاحقًا.

### 2.4.2 — ثبات قائمة الطالب ومراجعة المسارات
- أُصلح اختفاء قائمة أزرار الطالب بعد فتح «📚 دروس اليوم» أو شاشة داخلية؛ يحتفظ البوت برسالة القائمة الثابتة وينظف رسائل الشاشات المؤقتة فقط.
- تراعي إشعارات الدروس اليدوية والتلقائية والتذكيرات الإجازات المعتمدة وفق تاريخ بغداد، ويظهر للأدمن عدد الطلبة الذين تخطّاهم الإرسال بسبب الإجازة.
- صار منع الحضور بعد انقضاء المهلة ذريًا داخل قاعدة البيانات، ولا تحتسب التقارير إلا التأشيرات المسجلة ضمن مهلة الدرس.
- أضيف قفل يمنع تداخل دورات التذكير الدورية، ولا تُعلَّم رسالة العودة من الإجازة كمرسلة إلا بعد نجاح إرسالها فعلًا.
- حسّنت التحقق من مدخلات الأدمن: أسماء المراحل والمواد، الهاشتاغات، والاسم الرباعي للطالب.
- وُحّد اسم ملف إعدادات المثال إلى `.env.example` كما هو مذكور في دليل النشر.

### 2.4.1 — تسمية «المتغيرات»
- تغير اسم زر سجل الطالب إلى «📋 المتغيرات»؛ ويعرض الإجازات المعتمدة والتنبيهات المستلمة خلال الموسم الحالي.
- إذا لم يتلقَّ الطالب أي تنبيه، يُحذف قسم التنبيهات كاملًا من السجل ولا تظهر عبارة «لا توجد تنبيهات».

### 2.4.0 — رجوع، ألوان، انتقال للقناة، وتنظيف واجهة الطالب
- أضيف زر «↩️ رجوع» لإلغاء خطوة الإدخال الحالية والعودة إلى القائمة الرئيسية للطالب أو الأدمن.
- أضيفت أنماط ألوان تليجرام الرسمية لكل أزرار الرد والأزرار المضمنة بحسب معناها.
- تغير زر الاستماع إلى «📢 انتقال إلى دروس اليوم»، ويفتح منشور الدرس نفسه في قناة المرحلة المرتبطة.
- صارت رسائل تنقل الطالب القديمة تُحذف تلقائيًا عند فتح شاشة جديدة؛ ولا تُحذف التنبيهات المهمة المرسلة تلقائيًا.
- أضيف سجل للطالب يعرض الإجازات المعتمدة وتنبيهات الغياب في الموسم الحالي (أعيدت تسمية زره إلى «📋 المتغيرات» في 2.4.1).
- أُلغي حد منع تفعيل المادة نفسها خلال 15 دقيقة؛ يمكن الآن نشر أي عدد من دروس المادة الواحدة في اليوم، ولكل درس مهلة مستقلة.

### 2.3.4 — إصلاح إلغاء عملية ربط القناة
- صار زر «❌ إلغاء العملية» وأي زر آخر من لوحة الأدمن يتجاوز فحص الرسالة المحوّلة، ويلغي حالة ربط القناة القديمة قبل تنفيذ الخيار الجديد.

### 2.3.3 — تبسيط طلب الإجازة
- أُلغيت خطوة إدخال تاريخ بداية الإجازة؛ يرسل الطالب عدد الأيام فقط، وتبدأ من يوم الطلب تلقائيًا حسب توقيت بغداد.
- يقبل البوت الأرقام الغربية والعربية الهندية والفارسية، مثل: `1` و`١` و`۱`.

### 2.3.2 — حذف التاريخ من اسم الموسم
- أُزيل تاريخ بدء الموسم وانتهائه من جميع القوائم والرسائل والتقارير وملفات CSV؛ يظهر اسم الموسم مع وسم «الحالي» أو «السابق» فقط عند الحاجة.

### 2.3.1 — استثناء الإجازات المعتمدة من الغياب
- دروس أيام الإجازة المعتمدة لا تُحسب غيابًا، ويقطع يوم الإجازة سلسلة الغياب المتتالي؛ فالغياب بعد الإجازة يبدأ سلسلة جديدة.
- يُنسب الدرس إلى يوم نشره أو تفعيله؛ لذلك يبقى درس الإجازة مستثنى حتى لو انتهت مهلته في اليوم التالي.
- إذا اعتمد الأدمن الإجازة بعد حفظ لقطة أحد أيامها، يصحح البوت اللقطة تلقائيًا إلى يوم إجازة غير محسوب.

### 2.3.0 — تأكيد الطالب الرسمي وتنبيهات الغياب المتتالي
- **زر إلزامي لأول استخدام** لتأكيد أن المستخدم مسجّل في المعهد بصفة طالب رسمي؛ تُحجب وظائف الطالب حتى التأكيد.
- **تنبيه مستقل للطالب بعد 3 أيام دراسية متتالية من الغياب الكامل**، وتقرير مستقل للأدمن بعد 10 أيام، مجمع من جميع المراحل.
- يُعتمد اليوم بعد انتهاء مهلة آخر درس فيه، ويُعد غيابًا كاملًا عندما لا يكون أي درس من دروس اليوم قد أُشّر ضمن مهلته. لا يسمح البوت أصلًا بتأشير الدرس بعد انتهاء مهلته.
- يبدأ رصد السلاسل من تاريخ تشغيل هذه النسخة لأول مرة، منعًا لإرسال تنبيهات مفاجئة عن سجل قديم عند الترقية.

### 2.2.0 — الحذف بنوعين، الإجازات، ورسالة الترحيب
- **حذف الطالب بنوعين**: أرشفة (تبقي كل البيانات ويمكن إعادة التفعيل) أو حذف نهائي (يمحو الطالب مع كل تسجيلاته وحضوره وإجازاته). ومثله حذف نهائي للمراحل (مع كل طلبتها وموادها ومواسمها وقنواتها) وللمواد (مع دروسها وحضورها).
- **نقل الطالب لمرحلة أخرى** يحتفظ بسجله السابق كاملًا في مرحلته القديمة (كان متاحًا؛ أُبرز في القائمة).
- **نظام الإجازات**: الطالب يحدد تاريخ البداية وعدد الأيام، يوافق الأدمن أو يرفض، ولا تصل إشعارات الدروس أيام الإجازة ولا تُحسب غيابًا. لا يمكن تأشير الدرس بعد انتهاء مهلته، ويمكن للطالب إلغاء إجازته والعودة في أي وقت.
- **رسالة ترحيب شرعية** لأول استخدام، بجهة المعهد والتنبيه على عدم جواز تأشير درس قبل متابعته.

### 2.1.1 — تصحيح تسمية المواسم
- **أُعيدت خطوة كتابة اسم الموسم** التي أُلغيت خطأً في 2.1.0. الآن يكتب الأدمن اسم الموسم كاملًا كما يريد (مثل «الموسم الأول 2026»)، ويضيف البوت تلقائيًا الوسم النسبي «(الحالي)»/«(السابق)» والتاريخ فقط — تمامًا كما هو مطلوب.
- **يمكن تطبيق اسم موسم واحد على عدة مراحل دفعة واحدة** (مثل «2026-2027»)، مع إعادة استخدام الاسم عبر السنوات؛ أُزيل قيد التفرد العام القديم على اسم الموسم (يُسقط تلقائيًا عند الترقية)، وبقي منع تكرار نفس الاسم داخل المرحلة الواحدة.
- تحقّقت من الترقية من قاعدة كانت تحمل القيد القديم: يُسقط القيد بأمان بلا فقد أي بيانات.

### 2.1.0 — (مُتجاوَزة) محاولة تسمية تلقائية بالكامل
- **حُذفت خطوة كتابة اسم الموسم يدويًا نهائيًا.** كل موسم يُسمّى الآن تلقائيًا برقم ثابت لكل مرحلة (الموسم الأول، الثاني...) لا يتغير أبدًا، ووسم نسبي «(الحالي)»/«(السابق)» يتحرك تلقائيًا مع كل موسم جديد، وتاريخ البدء/الانتهاء — فلا تلتبس البيانات مهما تكاثرت السنون.
- **«📊 تقريري» صار قائمة اختيار للطالب**: إن كان له أكثر من موسم يختار أي موسم يريد عرضه بدل أن يصله كل تاريخه دفعة واحدة. تقرير الأدمن الشامل («تقرير كل المواسم» من إدارة الطلبة) بقي كما هو يعرض كل شيء دفعة واحدة.
- **«🗂️ أرشيف المواسم» أُعيد بناؤه** ليكون حسب المرحلة (يعرض كل مواسمها بترقيمها التلقائي) بدل «الدفعة المسمّاة» التي أُلغيت.
- تحقّقتُ من الترقية من قاعدة بيانات لنسخة سابقة كانت تحمل اسم موسم يدويًا: تُقرأ البيانات القديمة بلا أي فقد، ويُستبدل الاسم اليدوي بالتسمية التلقائية في العرض فقط.

### 2.0.1 — إصلاحات بعد المراجعة والاختبار
- **تسمية الموسم الأول عند التثبيت الجديد**: كان أول موسم في أي تثبيت جديد يُسمّى «السجل السابق» (وهو اسم مخصص لترحيل بيانات نسخة قديمة)، فيظهر بهذا الاسم في كل التقارير والأرشيف. صار يُسمّى «الموسم الأول»، مع بقاء اسم «السجل السابق» للبيانات المُرحَّلة فعلًا من نسخة سابقة.
- **معالجة قديمة لمنع التكرار**: كانت هذه النسخة تمنع درسًا ثانيًا للمادة نفسها خلال 15 دقيقة وتكتفي بتنبيه الأدمن؛ أُلغي هذا القيد نهائيًا في 2.4.0، وأصبح كل منشور جديد درسًا مستقلًا.
- **تقليل تنبيهات الأدمن غير الضرورية**: كان أي منشور يحتوي رابطًا (حتى إعلان عادي) ويخلو من الهاشتاغ يُرسل تنبيهًا للأدمن، ويتكرر مع كل تعديل للمنشور. صار التنبيه مقصورًا على المنشورات التي تبدو دروسًا فعلًا (مرفق صوتي أو مرئي، أو رابط لمضيف وسائط مثل يوتيوب أو Google Drive).
